# AGENTS.md — Quick Reference for AI Agents

## Project Overview

Telegram bot that bridges Telegram ↔ OpenCode AI server. Users send `/code <query>` and receive streamed, token-by-token replies in Telegram. Two processes: **opencode serve** (HTTP API) + **Node.js bot** (long polling).

## Tech Stack

- **Runtime:** Node.js ≥ 18 (ESM, `"type": "module"`)
- **Dependencies:** `grammy` (Telegram), `@opencode-ai/sdk` (OpenCode client), `dotenv`
- **Package manager:** npm

## Common Commands

```bash
# Install dependencies
npm install

# Start full stack (opencode serve + bot) — recommended
npm start

# Start bot only (assumes opencode serve is already running)
npm run start:bot

# Start with auto-confirmation mode (danger mode)
npm run start:skip-permissions

# Start opencode serve manually
npm run serve

# Direct supervisor invocation with flags
node scripts/start.js [--skip-permissions] [--no-serve]

# Shell wrapper (Linux/macOS)
./start-bot.sh [--skip-permissions] [--no-serve]
```

## Environment Variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `TELEGRAM_BOT_TOKEN` | *(required)* | Bot token from @BotFather |
| `TELEGRAM_ALLOWED_USERS` | *(empty → open to all)* | Comma-separated whitelist of Telegram user IDs (empty list disables the whitelist) |
| `OPENCODE_SERVER_URL` | `http://localhost:4096` | OpenCode HTTP API base URL |
| `OPENCODE_SERVER_USERNAME` | `opencode` | Basic Auth username |
| `OPENCODE_SERVER_PASSWORD` | *(required)* | Basic Auth password (auto-generated by `opencode serve`) |
| `DEFAULT_MODEL_PROVIDER` | `opencode` | Default model provider |
| `DEFAULT_MODEL_ID` | `big-pickle` | Default model ID |
| `OPENCODE_PORT` | `4096` | Port for `opencode serve` |
| `OPENCODE_HOST` | `127.0.0.1` | Host for `opencode serve` |
| `OPENCODE_BIN` | `opencode` / `opencode.cmd` | Path to opencode binary |
| `TELEGRAM_THROTTLE_MS` | `1000` | Min interval between Telegram message edits |
| `SSE_IDLE_TIMEOUT_MS` | `300000` (5 min) | SSE subscription idle timeout |
| `DEBUG_UPDATES` | `false` | Log all incoming Telegram updates verbosely |
| `OPENCODE_SUPERVISOR_PID` | *(set by supervisor)* | PID of the supervisor process (internal) |

## Source File Guide

| File | Responsibility |
|------|---------------|
| `src/index.js` | Bot entry point, all Telegram command handlers (`/code`, `/stop`, `/new`, `/model`, `/models`, `/sessions`, `/switch`, `/session`, `/projects`, `/danger`) |
| `src/opencode-client.js` | Lazy-initializes `@opencode-ai/sdk` client with Basic Auth |
| `src/session-store.js` | File-backed (`data/sessions.json`) chatId → sessionId mapping |
| `src/user-store.js` | File-backed (`data/users.json`) per-chat model preferences |
| `src/stream-handler.js` | SSE subscription + streamed response rendering with throttled Telegram edits |
| `src/message-formatter.js` | Splits long messages into ≤4000-char parts for Telegram |
| `scripts/start.js` | Cross-platform supervisor: starts `opencode serve`, waits for port readiness, launches bot, handles `/danger` flag restarts |

## Key Workflows

### Supervisor lifecycle (`scripts/start.js`)

1. Preflight: frees port (kills stale `opencode serve`), kills stale bot processes (`src/index.js`)
2. Starts `opencode serve` with optional `--dangerously-skip-permissions`
3. Waits for TCP connection on configured host:port
4. Starts bot as child process, sets `OPENCODE_SUPERVISOR_PID`
5. On bot exit: if `data/danger.flag` exists → reads mode → restarts both processes; otherwise exits
6. On `opencode serve` exit → stops bot too
7. `SIGINT`/`SIGTERM` → graceful shutdown of both children

### `/danger on|off` flow

1. Bot writes mode to `data/danger.flag` and exits (`process.exit(0)`)
2. Supervisor detects flag on bot exit, reads mode
3. Supervisor restarts `opencode serve` with or without `--dangerously-skip-permissions`
4. Supervisor restarts bot

### Streaming response flow (`src/stream-handler.js`)

1. Bot sends placeholder message "⏳ печатает..."
2. Subscribes to SSE events (`client.event.subscribe()`)
3. Sends `client.session.prompt()` with model selection
4. Accumulates `session.part` text events into a buffer
5. Throttled edits of the Telegram message (every `TELEGRAM_THROTTLE_MS`)
6. On `session.done` or `session.continue` → finalizes with "✅ Готово"
7. Handles 429 rate limits with retry-after backoff
8. `AbortController` per request — `/stop` aborts both prompt and SSE

## Data Files (gitignored)

- `data/sessions.json` — maps Telegram chatId to OpenCode sessionId
- `data/users.json` — per-chat model preferences (`provider` + `modelId`)
- `data/danger.flag` — temporary flag for supervisor restart signaling

## Access Control

- `TELEGRAM_ALLOWED_USERS` whitelist (comma-separated Telegram user IDs)
- Empty list = bot is open to all (with warning logged at startup)
- Middleware rejects unauthorized users with "⛔ У вас нет доступа"

## Notes

- The project uses **ESM** throughout (`"type": "module"` in package.json); use `import`/`export`, not `require`.
- `data/` directory is gitignored; `mkdirSync(..., { recursive: true })` ensures it exists at runtime.
- `start-bot.ps1` and `start-bot.sh` are thin wrappers that delegate to `scripts/start.js`.
- Telegram message edit limit is ~1/sec per chat; `TELEGRAM_THROTTLE_MS` controls the interval.
- Messages longer than 4000 chars are split by `splitMessage()` with part numbering.
